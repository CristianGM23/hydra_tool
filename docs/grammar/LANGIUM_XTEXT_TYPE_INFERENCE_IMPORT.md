# Importing hand-written Langium and Xtext grammars: type inference

The textual grammar importer (`TextualGrammarImportParser`, `TextualGrammarTypeInference`, `TextualGrammarModelEngine`) builds the neutral
metamodel from the types the grammar language itself infers. What HYDRA generates is unchanged (R6C3, `GeneratedGrammarMetamodelImporterTests`).
The import stays STRUCTURAL: every construct it cannot represent is reported with a warning, never dropped silently.

## Constructs

| Construct | Imported as |
|---|---|
| `R infers T:` and an unqualified `R returns T:` (not a data type) | Class `T` (D-1/D-2). Every rule that produces `T` contributes its features to the same class; references to `R` resolve to `T`. |
| `R returns model::T:` (qualified) | Class `T` (as before). |
| `X returns T: A \| B` (alternatives only) | No class `X`; what `A` and `B` produce becomes a subtype of `T`. |
| `{X}`, `{infer X}` inside a rule | Class `X`, subtype of the rule's type, with the features assigned after the action along the parse path (D-3). A leading action that names the rule's own type (what HYDRA generates) creates nothing new. |
| `{X.f=current}`, `{infer X.f+=current}` (rewrite actions, the classic precedence encoding) | Class `X` with the containment `f` typed by the rule's type, plus the features that follow on the parse path, also after the group that holds the action (`(({Plus.left=current} '+' \| {Minus.left=current} '-') right=M)*` gives `right` to `Plus` and `Minus`). |
| A rule alternative that starts with an unassigned rule call, in a rule with `infers`/`returns` or actions | The called rule's type is a subtype of the rule's type (`Mult infers Expr: Prim (…)*` makes `Prim` an `Expr`). |
| `infix B on P: '%' > '^' > '*' \| '/' …;` (Langium ≥ 3.3) | Class `B` with containments `left`/`right` typed by what `P` produces and attribute `operator`, an enumeration whose literals keep the operators as serialized values. Annotations `infix:operand` and `infix:precedence` (groups from the strongest, as declared) (D-4). |
| `E: B;` where another rule also produces `E` | `E` is a real supertype and `B`'s type a subtype of it (D-5). When no other rule produces `E`, the forwarding rule is still resolved to `B` and reported with `IMPORT_INFO_FORWARDING_RULE_RESOLVED`, as before. |
| `fragment F: …;` | Inlined into every rule that calls `F` (also nested). |
| `terminal T returns number: …;` | Features assigned with `T` get the terminal's primitive type (`string` when it declares none); no placeholder class is created for a terminal. |
| `R<Param>:` (rule parameters, guards) | Imported under the rule's own name; parameters only guide parsing. |
| A Langium type that only unites its subtypes (no own features) | Abstract class (Langium generates `type T = A \| B`). Xtext keeps a concrete EClass. |

When one class gathers several rules or actions, a feature assigned in several places is one feature if the occurrences have the same
operator and either the same expression, targets of which one is a supertype of the other (the feature is typed by the more general one),
terminals of the same primitive type, or keyword groups (their literals are united). Anything else stays a renamed, warned conflict.

## Representation (compatible, no schema change)

Only annotations are added; the neutral metamodel schema is unchanged:

- class: `sourceRules` (rules that contributed to the class), `inferredByAction`, `infix:operand`, `infix:precedence`;
- inheritance relation: `inference=grammar-type`, besides the existing `inferred=true`.

## Limits (reported)

- `import "other"` is not followed: types and supertypes declared in another grammar file are not imported (single-file import).
- Xtext lifts the features shared by every subtype to their common supertype; the STRUCTURAL import keeps them on each subtype.
- An action written in a form the importer does not read is reported with `IMPORT_GRAMMAR_ALTERNATIVE_ACTIONS_MERGED`.

## Verification

`GrammarTypeInferenceImportTests` covers each construct and compares six real grammars (`src/test/resources/grammar-real`, pinned commits and
licenses in `PROVENANCE.md`) with the types their language infers: for Langium, the `ast.ts` generated by langium-cli 4.4.0.
