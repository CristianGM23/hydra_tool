# Transformation toolchain closure

R5C13 Fix49 final treats the HYDRA transformation-toolchain implementation as closed at the product boundary.

The canonical transformation definition and HYDRA canonical runtime remain the semantic source of truth. Native parity never changes that contract. Java, Python and Go include independent managed runtimes for their demonstrated exact subsets. ATL, ETL, Acceleo, EGL and Xtend are integrated through trusted JVM classpath packages whose third-party engines are supplied by the deployment administrator.

A missing third-party engine is an installation state, not unfinished HYDRA behavior: the official bridge diagnoses it as unavailable and refuses execution. A full package becomes executable only after complete checksum-verified engine and HYDRA driver payloads are present. No browser request can provide an executable, path, archive or classpath.

The final runtime capability matrix remains deliberately bounded: M2M reverse evidence is directional parity, not proof of full bidirectional synchronization; M2T is forward-only; full external bidirectional and incremental synchronization flags remain false until an external engine preserves both sides, baselines, correspondence identity and conflict semantics in one managed execution.
